# Contributing

Use focused changes and explain the behavior affected. For commits, use a short imperative summary such as `feat(stats): add a metric`, `fix(hud): correct alignment`, or `docs: clarify installation`. Keep unrelated changes in separate commits.

Pull requests should describe the observed problem, the resulting behavior and checks actually performed. Separate mocked tests from in-game and multiplayer evidence. Include reproduction steps, game/UE4SS versions and language for UI issues.

Do not commit player records, Steam IDs captured from a session, personal paths, credentials, vendor SDKs or game binaries. Use synthetic test fixtures. Preserve applicable licenses.
